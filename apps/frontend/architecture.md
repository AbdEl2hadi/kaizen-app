# Frontend Architecture

TanStack Start application (React + Vite) using **TanStack Router**
(file-based routing) and **TanStack Query** for server-state.

## Source Layout (`src/`)

```
src/
├── router.tsx                     # Router factory + QueryClient context
├── routeTree.gen.ts               # AUTO-GENERATED by `tsr generate` — do not edit
├── styles.css                     # Tailwind entry + design tokens
├── routes/                        # FILE-BASED ROUTES (TanStack Router)
│   ├── __root.tsx                 # Root layout: <html>, global providers, devtools
│   ├── index.tsx                  # Home page
│   ├── _layout.tsx                # Layout groups (`_` prefix) with <Outlet />
│   └── _layout/
│       └── ... guarded/paginated routes
├── components/                    # Presentational components
│   ├── ui/                        # shadcn/ui primitives (button, input, dialog...)
│   ├── shared/                    # Reusable cross-feature components
│   ├── layout/                    # App shell pieces (sidebar, topbar, nav)
│   └── <page>/                    # Page-specific sections
├── features/                      # FEATURE-SCOPED modules (domain code)
│   └── <feature>/
│       ├── api/                   # Query options + mutation hooks
│       ├── hooks/                 # Form/logic hooks
│       ├── schema/                # zod schemas shared with forms
│       ├── components/            # Feature-specific components (optional)
│       ├── guard.ts               # Route guards (if the feature gates routes)
│       └── types.ts               # Feature types
├── integrations/                  # Third-party library wiring (one folder per lib)
│   └── <library>/
│       ├── root-provider.tsx      # Provider/context factory
│       └── devtools.tsx
├── providers/                     # App-wide context providers
├── hooks/                         # Cross-feature shared hooks
├── lib/                           # Cross-cutting, dependency-free helpers
│   ├── api.ts                     # HTTP client instance + response types
│   ├── env.ts                     # Validated env access
│   └── utils.ts                   # cn() and other helpers
├── constants/                     # Static config values, query-key factories
├── types/                         # App-wide types shared across features
└── public/                        # Static assets (logos, images, icons)
```

## Folder Responsibilities

| Folder              | Responsibility                                             |
| ------------------- | ----------------------------------------------------------- |
| `routes/`           | File-based routes + their loaders/guards. Never hand-edit `routeTree.gen.ts`. |
| `components/`       | Presentational UI. `ui/` for shadcn primitives, `shared/` for cross-feature, `layout/` for app shell. |
| `features/`         | Domain logic per feature (`api`, `hooks`, `schema`, `types`). One folder per domain. |
| `integrations/`     | Adapters that wrap third-party libraries (Query, etc.).     |
| `providers/`        | App-wide React contexts (theme, i18n, etc.).                |
| `hooks/`            | Shared hooks used by more than one feature.                 |
| `lib/`              | Pure utilities and infrastructure (HTTP client, env, helpers). |
| `constants/`        | Static values (routes, query keys, config).                 |
| `types/`            | App-wide types shared across features.                      |
| `public/`           | Static assets served as-is.                                  |

## Key Patterns

### Routing
Routes are files in `src/routes`. Run `tsr generate` to rebuild
`routeTree.gen.ts` — never hand-edit it. Use `beforeLoad` + guards to gate
access and layout groups (leading `_`) to share chrome between routes.

### Data fetching
- One HTTP client in `src/lib/api.ts`.
- Feature-level API functions return a typed response envelope.
- React Query `queryOptions` / mutation hooks live in `features/<feature>/api/`.

### Feature structure
Add a new domain by creating `src/features/<name>/` with the same sub-layout
as any existing feature:

```
features/<name>/
├── api/          # queryOptions + mutation hooks
├── hooks/        # reusable logic hooks (forms, derived state)
├── schema/       # zod schemas
├── components/   # feature-specific components (optional)
├── types.ts      # feature types
└── guard.ts      # route guards (if the feature gates routes)
```

### Environment variables
Validate `import.meta.env` at startup and throw on invalid config.

## Decision Rules

1. **New domain logic →** `src/features/<feature>/`; never dump it in
   `components/` or `lib/`.
2. **Reusable presentational primitives →** `components/ui/` (via shadcn) or
   `components/shared/`; feature-specific UI → the feature folder.
3. **Shared hooks →** `src/hooks/`; shared pure utils → `src/lib/`.
4. **Cross-feature contracts** (shared types/zod schemas) go in `src/types/`
   or `src/constants/` only when two+ features need them; otherwise keep them
   inside the feature.
